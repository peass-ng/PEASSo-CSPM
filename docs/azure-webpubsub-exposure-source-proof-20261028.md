# Azure Web PubSub exposure source proof

The read-only [Web PubSub GET](https://learn.microsoft.com/en-us/rest/api/webpubsub/controlplane/web-pub-sub/get?view=rest-webpubsub-controlplane-2024-03-01) supplies public network ACLs and service ports. The existing cached private-endpoint child LIST supplies approvals and remote endpoint IDs. [Web PubSub network controls](https://learn.microsoft.com/en-us/azure/azure-web-pubsub/howto-secure-network-access-control) apply request-type ACLs to each named private endpoint; public IP rules do not block private links. Native analysis joins the foreign approved connection to its effective request rights even when public access is disabled.

The read-only paged [hub LIST](https://learn.microsoft.com/en-us/rest/api/webpubsub/controlplane/web-pub-sub-hubs/list?view=rest-webpubsub-controlplane-2024-03-01) exposes anonymous connect policy, event handlers, event listeners, and persistent storage. The [shared private link LIST](https://learn.microsoft.com/en-us/rest/api/webpubsub/controlplane/web-pub-sub-shared-private-link-resources/list?view=rest-webpubsub-controlplane-2024-03-01) exposes approved outbound integrations. The collector validates child identities and keeps only target host/port, Event Hub name, resource IDs, and policy flags. Handler URL paths, queries, and request messages remain in the in-memory response cache and are absent from snapshots.

Native analysis marks public anonymous hubs and configured outbound destinations, with UNKNOWN where target ownership or event flow is unresolved. [Client access tokens](https://learn.microsoft.com/en-us/azure/azure-web-pubsub/howto-generate-client-access-url) can be generated by an application server or SDK; the portal's token generator explicitly does not store the inputs. ARM has no read operation that enumerates issued client JWTs or their recipients, so complete token-based third-party access enumeration is impossible from a read-only scan.
