# Azure DocumentDB Mongo cluster exposure source proof

The existing read-only `Microsoft.DocumentDB/mongoClusters` LIST and GET use API `2026-06-01`, which includes [publicNetworkAccess, dataApi.mode, and networkBypassMode](https://learn.microsoft.com/en-us/azure/templates/microsoft.documentdb/change-log/mongoclusters). The parent projection omits administrator credentials and connection strings. The extension reads cached, paged firewall-rule and Entra-user LISTs. It reuses embedded private endpoint connections from the parent GET when present, otherwise reads the private endpoint connection LIST once. Only IDs, approval/provisioning state, IP ranges, principal types, and role names enter the snapshot.

The [firewall rule ARM schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.documentdb/2025-09-01/mongoclusters/firewallrules) supplies start and end IPv4 addresses. The [public access guide](https://learn.microsoft.com/en-us/azure/documentdb/how-to-public-access) says no firewall rules means public access is blocked, and the all-Azure rule grants attempts from other customers' subscriptions. The [DocumentDB troubleshooting guide](https://learn.microsoft.com/en-us/azure/documentdb/troubleshoot-common-issues) identifies Mongo port 10260. The [Data API guide](https://learn.microsoft.com/en-us/azure/documentdb/data-api) identifies a separate HTTPS endpoint on port 443 when `dataApi.mode` is enabled.

The [private endpoint resource schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.documentdb/mongoclusters/privateendpointconnections) exposes approval state. An approved link to another subscription is a private third-party route, subject to database authentication. The [Entra RBAC guide](https://learn.microsoft.com/en-us/azure/documentdb/how-to-connect-role-based-access-control) documents `mongoClusters/users` LIST and database role grants; the user ID alone does not prove its tenant, so those grants are reported as conditional. The [network bypass mode](https://learn.microsoft.com/en-us/azure/cosmos-db/mongodb/how-to-migrate-documentdb) is also reported as conditional access to the Azure Cosmos DB service.
