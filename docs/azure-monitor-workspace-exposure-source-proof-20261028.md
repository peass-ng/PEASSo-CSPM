# Azure Monitor workspace query and private-share source proof

The [Azure Monitor workspace LIST API](https://learn.microsoft.com/en-us/rest/api/monitor/azure-monitor-workspaces/list-by-subscription?view=rest-monitor-2023-04-03) returns the Prometheus query URL, provisioning state, public network access setting and private endpoint connections. The existing network catalog selects `Microsoft.Monitor/accounts` with API version `2025-10-03`; its [current ARM schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.monitor/2025-10-03/accounts) includes `publicNetworkAccess`. [Private-link guidance](https://learn.microsoft.com/en-us/azure/azure-monitor/fundamentals/private-link-azure-monitor-workspace) confirms that disabling public access blocks the public query endpoint while approved private endpoints provide private query access.

The collector already issues the subscription LIST. A narrow projection now retains only the validated `*.prometheus.monitor.azure.com` query hostname, public access and provisioning state, and private endpoint IDs, statuses and group IDs. It discards query URL paths and query strings and all unrelated workspace fields. Native analysis reports an authenticated public TCP/443 endpoint only for a succeeded workspace with `publicNetworkAccess=Enabled` and a valid query host. It reports an approved, succeeded `prometheusMetrics` private link to another subscription even when public access is disabled. Missing network or connection evidence remains `UNKNOWN`.

The management API does not enumerate every holder of a valid query token, nor the viewers to whom a separate Grafana deployment may expose its dashboards. Those downstream application permissions cannot be decided from workspace configuration alone.
