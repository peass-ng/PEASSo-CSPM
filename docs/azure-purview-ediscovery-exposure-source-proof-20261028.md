# Microsoft Purview eDiscovery case membership

- [List eDiscovery cases](https://learn.microsoft.com/en-us/graph/api/security-casesroot-list-ediscoverycases?view=graph-rest-1.0) and [list case members](https://learn.microsoft.com/en-us/graph/api/security-ediscoverycasemember-list?view=graph-rest-1.0) document read-only Microsoft Graph v1.0 endpoints. Both accept application `eDiscovery.Read.All` where the tenant's licensing and authorization permit it. The case-member result includes `id` and `recipientType` (`user` or `roleGroup`). [The member resource](https://learn.microsoft.com/en-us/graph/api/resources/security-ediscoverycasemember?view=graph-rest-1.0) states that members are granted access to a case and its data.
- [Purview eDiscovery access settings](https://learn.microsoft.com/en-us/purview/edisc-settings-access-permissions) documents guest access and case membership. [The Graph eDiscovery API overview](https://learn.microsoft.com/en-us/graph/api/resources/security-ediscovery-apioverview?view=graph-rest-1.0) describes E3/E5 and app-only availability. A denied read remains incomplete inventory, not an empty case list.

`azure_purview_ediscovery_native.collect` reads the case LIST once and each observed case's member LIST once through the shared per-scan cache and page budget. It projects only case status and case/member IDs and drops case names, descriptions and member email addresses. `internet_exposure._azure_purview_ediscovery_case_member` reports an active case's direct Guest user member when that member ID resolves to the collected Graph directory user. Role-group membership and non-active cases remain `UNKNOWN` until effective access can be attributed.
