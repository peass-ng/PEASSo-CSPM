# Azure Red Hat OpenShift exposure source proof

The read-only [Open Shift Clusters GET](https://learn.microsoft.com/en-us/rest/api/openshift/standard/open-shift-clusters/get?view=rest-openshift-standard-2025-07-25) returns `apiserverProfile.visibility`, its URL/IP, and the `ingressProfiles` names, visibility, and IPs. [The ARM resource schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.redhatopenshift/openshiftclusters) defines `Public` and `Private` visibility for both surfaces. The existing cached cluster LIST is followed by one GET per cluster to obtain these effective fields. Native analysis reports the API URL's TCP port and public router ports 80/443; private profiles block those paths, and missing/malformed fields remain UNKNOWN.

The collector removes `clusterProfile.pullSecret` and `servicePrincipalProfile.clientSecret` before saving the resource. The focused test verifies both are absent, that each cluster detail is fetched once, and that public, private, and malformed URL outcomes are distinct. ARM does not enumerate OpenShift workload Routes, Services, or their access policies; those require a separate cluster API scan. This limit is recorded in each public finding.
