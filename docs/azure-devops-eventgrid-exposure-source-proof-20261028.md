# Azure DevOps and Event Grid exposure source proof

The [Azure DevOps Projects GET API](https://learn.microsoft.com/en-us/rest/api/azure/devops/core/projects/get?view=azure-devops-rest-7.1) returns `visibility: public|private`. Microsoft's [public project retirement notice](https://learn.microsoft.com/en-us/azure/devops/organizations/projects/public-projects-retirement?view=azure-devops) says existing public projects expose code, work items, wikis, pipelines, and artifacts anonymously until conversion in 2027. The existing owner-bound DevOps collector already reads project LIST and GET once. It now retains only matching visibility from both reads; the native assessment marks a public project as anonymous data access, a private project as blocked for that path, and inconsistent or absent visibility UNKNOWN. This is project-wide visibility, not an effective ACL audit of every private-project member or feed.

The [Event Grid topic and domain networking guide](https://learn.microsoft.com/en-us/azure/event-grid/configure-firewall) says public network access is enabled by default and inbound IP rules can restrict public publishing. The [topic ARM schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.eventgrid/2025-02-15/topics) supplies `endpoint`, `publicNetworkAccess`, and `inboundIpRules`. The existing collector lists topics and domains once per subscription. The native assessment reports the HTTPS/443 publishing surface when public access is enabled with no IP restrictions or with a public source, blocks the public path when access is disabled or rules contain only private sources, and retains malformed data as UNKNOWN. Event subscriptions and namespace MQTT/HTTP ingress remain UNKNOWN residual paths. The [global subscription LIST API](https://learn.microsoft.com/en-us/rest/api/eventgrid/controlplane/event-subscriptions/list-global-by-subscription?view=rest-eventgrid-controlplane-2025-02-15) exposes destinations, including webhook base URLs, for future recipient assessment.
