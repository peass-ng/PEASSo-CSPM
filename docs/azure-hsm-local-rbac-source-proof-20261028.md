# Managed HSM local RBAC source proof (2026-10-28)

Managed HSM key/data access is controlled by [HSM local RBAC](https://learn.microsoft.com/en-us/azure/key-vault/managed-hsm/access-control), separately from ARM RBAC. The ARM HSM response supplies `properties.hsmUri`; the collector validates that its Microsoft Managed HSM hostname matches the selected ARM HSM name before allowing a data-plane request with the existing Key Vault token audience.

The collector makes paged, read-only [Role Assignments - List For Scope](https://learn.microsoft.com/en-us/rest/api/keyvault/managedhsm-administration/role-assignments/list-for-scope?view=rest-keyvault-managedhsm-administration-2025-07-01) GETs at the HSM `/` and `/keys` scopes with API version 2025-07-01. It validates local assignment IDs, principal IDs, role-definition references and scopes; only those metadata fields are retained. Denied or partial reads retain coverage status. Observed outside principals become native principal-exposure findings for declared local HSM grants.

Microsoft states that these top-level LISTs do not enumerate individual `/keys/{key-name}` assignments. The collector now uses the paged, read-only [Get Keys](https://learn.microsoft.com/en-us/rest/api/keyvault/keys/get-keys/get-keys?view=rest-keyvault-keys-2025-07-01) operation to discover key names, retains only their identifiers, and reads [Role Assignments - List For Scope](https://learn.microsoft.com/en-us/rest/api/keyvault/managedhsm-administration/role-assignments/list-for-scope?view=rest-keyvault-managedhsm-administration-2025-07-01) at each observed `/keys/{key-name}` scope. A failed key inventory or scoped assignment read keeps local RBAC coverage partial.

The collector also makes a paged, read-only [Role Definitions - List](https://learn.microsoft.com/en-us/rest/api/keyvault/managedhsm-administration/role-definitions/list?view=rest-keyvault-managedhsm-administration-2025-07-01) GET at `/keys`, whose contract includes definitions applicable at that scope and above. It retains action and data-action grants and exclusions, and attaches a matching definition to the observed outside-principal finding. A denied or malformed definition list remains visible in coverage. This is declared permission evidence, not a simulation of effective HSM authorization or PIM activation.
