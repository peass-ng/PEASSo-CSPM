# Microsoft Entra Domain Services exposure source proof

- The [2022-12-01 ARM schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.aad/2022-12-01/domainservices) exposes `ldapsSettings.ldaps` and `.externalAccess`, replica subnets and public LDAPS addresses, notification recipients, and forest-trust domain/direction. The same schema has `pfxCertificate`, `pfxCertificatePassword`, and `trustPassword`; the collector projects none of these, using one paged subscription LIST per scan.
- The [Microsoft secure LDAP tutorial](https://learn.microsoft.com/en-us/azure/active-directory-domain-services/tutorial-configure-ldaps) states that enabling external LDAPS makes TCP 636 reachable through the managed domain public address, subject to subnet NSG restrictions. Native analysis joins the domain replica subnet/controller address to the existing subnet and NSG inventory. It reports a proven open public path as FAIL, a collected NSG block as PASS, and missing path data as UNKNOWN.
- Off-domain notification recipients and configured forest trusts are recorded as conditional evidence because a domain absent from verified Entra domains can still belong to the same organization. [LDAP binds use domain credentials](https://learn.microsoft.com/en-us/azure/active-directory-domain-services/tutorial-configure-ldaps); the ARM resource does not enumerate possession of those credentials or effective directory ACLs. This prevents a complete read-only ARM determination of every third party that can read a reachable managed domain.
