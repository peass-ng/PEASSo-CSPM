# Azure Web PubSub delivery exposure source proof

Microsoft's [Web PubSub hub LIST API](https://learn.microsoft.com/en-us/rest/api/webpubsub/controlplane/web-pub-sub-hubs/list?view=rest-webpubsub-controlplane-2024-03-01) returns each hub's event handlers, Event Hub event listeners, and `anonymousConnectPolicy`. The [upstream server guide](https://learn.microsoft.com/en-us/azure/azure-web-pubsub/howto-web-pubsub-write-upstream-server) states that handlers receive client event metadata and request bodies over HTTP. The [hub schema](https://learn.microsoft.com/en-us/rest/api/webpubsub/controlplane/web-pub-sub-hubs/create-or-update?view=rest-webpubsub-controlplane-2024-03-01) defines `eventListeners[].endpoint` as an Event Hub namespace and hub name; the listener forwards matching client events without interrupting the client.

The collector performs one cached paged hub LIST per selected Web PubSub resource. It validates hub ownership and retains only HTTP receiver hostnames, Event Hub namespace names, and the anonymous-connect policy. URL paths, query tokens, webhook authentication settings, and event payloads are never stored in the snapshot. The native detector reports an HTTP event receiver, or an Event Hub listener matched to a namespace in another selected subscription. A namespace hostname with no authoritative Event Hubs inventory match remains `UNKNOWN`, because the hub API does not include its subscription or tenant ID. Failed or incomplete hub LISTs also remain `UNKNOWN`.

The existing Web PubSub listener assessment evaluates public network access, public request types, and IP ACLs. When its public client path is open, the new hub facts also record an `allow` anonymous-connect policy as unauthenticated client access. A configured handler or listener is assessed independently of public ingress because a private client can still produce forwarded events.
