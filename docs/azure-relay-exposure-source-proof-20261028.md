# Azure Relay exposure source proof

The existing generic ARM collector reads each `Microsoft.Relay/namespaces` parent once. The Relay extension reuses that item and adds cached, paged, read-only LIST calls for namespace authorization rules, hybrid connections, WCF relays, and each entity's authorization rules. It projects IDs, public network state, listener counts, client authorization, binding type, approved private links, and SAS rights; it does not copy keys or entity metadata. A child-read failure remains an unknown coverage state.

The [namespace LIST schema](https://learn.microsoft.com/en-us/rest/api/relay/namespaces/list?view=rest-relay-2024-01-01) specifies `publicNetworkAccess`, private endpoint connections, and the service endpoint. The [hybrid connection LIST](https://learn.microsoft.com/en-us/rest/api/relay/hybrid-connections/list-by-namespace?view=rest-relay-2024-01-01) and [WCF relay LIST](https://learn.microsoft.com/en-us/rest/api/relay/wcf-relays/list-by-namespace?view=rest-relay-2024-01-01) expose listener counts and client authorization settings. [Namespace](https://learn.microsoft.com/en-us/rest/api/relay/namespaces/list-authorization-rules?view=rest-relay-2024-01-01), [hybrid](https://learn.microsoft.com/en-us/rest/api/relay/hybrid-connections/list-authorization-rules?view=rest-relay-2024-01-01), and [WCF](https://learn.microsoft.com/en-us/rest/api/relay/wcf-relays/list-authorization-rules?view=rest-relay-2024-01-01) authorization-rule LISTs expose SAS rights. [Relay port settings](https://learn.microsoft.com/en-us/azure/azure-relay/relay-port-settings) identify TLS/WebSocket and WCF client ports. Issued SAS tokens and recipients are not enumerable from these rule LISTs, so rights are reported as conditional exposure.
