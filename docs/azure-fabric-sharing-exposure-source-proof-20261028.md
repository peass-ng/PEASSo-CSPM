# Microsoft Fabric and Power BI sharing: source proof

- Fabric [admin workspaces LIST](https://learn.microsoft.com/en-us/rest/api/fabric/admin/workspaces/list-workspaces) returns tenant-wide workspace IDs and continuation tokens. Its documented limit is 200 requests/hour.
- Fabric [admin workspace access-details GET](https://learn.microsoft.com/en-us/rest/api/fabric/admin/workspaces/list-workspace-access-details) returns user, group, service-principal and entire-tenant grants with workspace roles. The response is preview and limited to 200 requests/hour. `azure_fabric_workspace_native` retains only IDs, principal types and roles.
- Fabric [admin items LIST](https://learn.microsoft.com/en-us/rest/api/fabric/admin/items/list-items) returns tenant-wide item IDs, types and workspace IDs with continuation tokens. Fabric [admin item access-details GET](https://learn.microsoft.com/en-us/rest/api/fabric/admin/items/list-item-access-details) returns item permissions by principal. The collector drops names, descriptions, UPNs and other unneeded fields.
- Power BI [PublishedToWeb](https://learn.microsoft.com/en-us/rest/api/power-bi/admin/widely-shared-artifacts-published-to-web) and [LinksSharedToWholeOrganization](https://learn.microsoft.com/en-us/rest/api/power-bi/admin/widely-shared-artifacts-links-shared-to-whole-organization) are tenant-wide admin GETs with continuation tokens. The collector projects artifact IDs, types and share kinds only. The Power BI token resource is [documented as `https://analysis.windows.net/powerbi/api`](https://learn.microsoft.com/en-us/power-bi/developer/embedded/troubleshoot-rest-api); the transport binds that audience to the two exact `api.powerbi.com` GET routes.
- [Organization-wide sharing links](https://learn.microsoft.com/en-us/power-bi/collaborate-share/service-share-dashboards) explicitly exclude external and guest users; native analysis records them as internal-only. Specific-person guest access is represented by item grants. An `EntireTenant` principal in an item or workspace response is kept UNKNOWN because its guest eligibility cannot safely be inferred from the principal type alone.
- Fabric [admin external data shares LIST](https://learn.microsoft.com/en-us/rest/api/fabric/admin/external-data-shares-provider/list-external-data-shares) is tenant-wide, paged and returns status plus the accepted recipient tenant ID for active shares. Native analysis detects active foreign-tenant data shares and ignores pending, revoked and expired invitations. The collector retains IDs, status, recipient tenant and path count, dropping shared paths, names, UPNs and invitation URLs.
- [Publish-to-web status](https://learn.microsoft.com/en-us/power-bi/collaborate-share/service-publish-to-web) can be Active, Blocked, Not supported or Infringed; disabling the feature can also disable existing codes without deleting them. The PublishedToWeb REST response has no status or public embed URL, while the [Fabric Admin portal](https://learn.microsoft.com/en-us/fabric/admin/service-admin-portal-embed-codes) exposes code management. Therefore a read-only API scan can identify configured anonymous publications but cannot decide effective anonymous availability of each embed code. Native analysis marks this `UNKNOWN`, with the configured public share in evidence.
- Admin listing is permission-gated, preview, and rate-limited. If a child access read is denied, the inventory keeps its parent with `role_assignments_status=unavailable`; other errors and page limits make the collection incomplete. No empty ACL is inferred from a failed read.
