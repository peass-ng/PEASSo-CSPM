# Azure AI Search private exposure source proof

The existing Azure collector lists `Microsoft.Search/searchServices` per subscription with the read-only cached ARM request. It validates each embedded private endpoint connection belongs to the observed service; malformed children set `_coverage.privateEndpointConnections.status=malformed` instead of becoming an empty list. No additional cloud call was added.

The [Search service LIST schema](https://learn.microsoft.com/en-us/rest/api/searchmanagement/services/list-by-subscription?view=rest-searchmanagement-2025-05-01) includes public network access, IP restrictions, and private endpoint IDs with approval and provisioning states. The [network configuration guide](https://learn.microsoft.com/en-us/azure/search/service-configure-firewall) describes private endpoints as the exclusive access path when public network access is disabled. An approved, provisioned endpoint in another subscription therefore gives that subscription a route to the service, subject to data-plane authorization. The detector records this separately from its public listener and keeps malformed private-link inventory unresolved when the public path is blocked.
