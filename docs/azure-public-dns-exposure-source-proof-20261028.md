# Azure Public DNS exposure source proof

[Microsoft's Azure Public DNS overview](https://learn.microsoft.com/en-us/azure/dns/public-dns-overview) says public zones are hosted on Azure's global name servers and answer DNS queries. The [zone GET API](https://learn.microsoft.com/en-us/rest/api/dns/zones/get?view=rest-dns-2018-05-01) returns the authoritative `nameServers` and `zoneType`, whose documented default is `Public`. The [Azure DNS overview](https://learn.microsoft.com/en-us/azure/dns/dns-overview) distinguishes internet-facing public DNS from private DNS zones. The [DNS FAQ](https://learn.microsoft.com/en-us/azure/dns/dns-faq) says zone transfers are unsupported and describes the four Azure name servers assigned to a zone.

The collector already lists `Microsoft.Network/dnsZones` once per selected subscription and record sets once per selected zone using the cached, paged reader. It now GETs each listed zone once before using the documented `zoneType` default or its name-server values. The native assessment reports a public authoritative TCP/UDP 53 DNS surface when a full GET establishes a public zone and valid name servers. A private zone blocks this path. Missing detail, unrecognized zone type, or malformed name servers remain UNKNOWN. Public DNS records are intentionally queryable; their presence does not establish that any referenced application accepts internet traffic.

The [Private DNS virtual network link LIST API](https://learn.microsoft.com/en-us/rest/api/dns/privatedns/virtual-network-links/list?view=rest-dns-privatedns-2018-09-01) returns each link's target VNet ARM ID, provisioning state, and link state. [Microsoft's Private DNS FAQ](https://learn.microsoft.com/en-us/azure/dns/dns-faq-private) says zone links can cross both subscriptions and tenants; [the VNet link guide](https://learn.microsoft.com/en-us/azure/dns/private-dns-virtual-network-links) says a linked VNet can query the private zone's records. The existing collector lists links once per zone through the paged reader. The native zone assessment marks a completed, succeeded link to a VNet outside the selected subscriptions as third-party DNS answer access, marks links within the selected subscriptions as internal, and leaves missing or transitional link evidence UNKNOWN. This check is limited to direct zone links. DNS Private Resolver inbound and outbound forwarding are separate routes and still require native assessment.
