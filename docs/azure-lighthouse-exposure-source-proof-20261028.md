# Azure Lighthouse delegation exposure source proof

The collector uses the read-only, paged [Registration Assignments LIST](https://learn.microsoft.com/en-us/rest/api/managedservices/registration-assignments/list?view=rest-managedservices-2022-10-01) with `$expandRegistrationDefinition=true` at each selected subscription and its collected resource groups. The expanded response binds each assignment to its registration definition, the managing and managed tenant IDs, active role authorizations, and eligible just-in-time authorizations. The collector validates that assignment IDs belong to the requested scope and referenced definitions belong to the same subscription; it omits display names and descriptions. A missing expanded definition remains unknown, with no second definition read.

The [Azure Lighthouse architecture](https://learn.microsoft.com/en-us/azure/lighthouse/concepts/azure-delegated-resource-management) explains that the assignment activates a definition at a subscription or resource-group scope, granting the managing tenant's principals their specified built-in roles without accounts in the customer tenant. Native analysis reports a successful active assignment to a different tenant as foreign access. Eligible-only roles remain conditional because activation depends on the just-in-time policy.
