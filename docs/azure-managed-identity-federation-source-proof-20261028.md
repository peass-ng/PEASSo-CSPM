# Managed identity federation exposure source proof

The existing selected `managed_identity_federated_credential` inventory lists user-assigned identities and each identity's federated credentials using read-only, cached ARM LIST calls. The credential LIST now uses `2025-05-31-preview`, whose [resource schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.managedidentity/userassignedidentities/federatedidentitycredentials) includes `claimsMatchingExpression` as well as the older exact `subject`. The collector retains issuer, audience and subject/expression without fetching tokens or secrets.

[Microsoft's workload federation documentation](https://learn.microsoft.com/en-us/entra/workload-id/workload-identity-federation-create-trust-user-assigned-managed-identity) says a matching token from the configured issuer can be exchanged for a token of the managed identity. A pinned subject therefore still grants that external workload access. Native trust analysis now reports that effective external issuer as an exposure. It treats an exact issuer URL matching a collected AKS cluster as owned, and leaves AKS ownership unresolved if the AKS inventory is incomplete. A flexible expression on an owned AKS issuer remains UNKNOWN because workload ownership is not derivable from the expression alone.
