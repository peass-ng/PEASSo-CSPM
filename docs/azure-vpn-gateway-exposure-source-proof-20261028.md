# Azure VPN Gateway exposure source proof

Microsoft's [VPN Gateway public-IP guide](https://learn.microsoft.com/en-us/azure/virtual-network/ip-services/configure-public-ip-vpn-gateway) identifies the gateway public IP as the external VPN connection point. The [gateway REST GET schema](https://learn.microsoft.com/en-us/rest/api/network-gateway/virtual-network-gateways/get?view=rest-network-gateway-2025-09-01) supplies `gatewayType`, `provisioningState`, public-IP configuration references, and Point-to-Site `vpnClientConfiguration` with `SSTP`, `OpenVPN`, and `IkeV2` protocol values. [Microsoft's P2S guide](https://learn.microsoft.com/en-us/azure/vpn-gateway/point-to-site-about) describes the client authentication modes. The [VPN FAQ](https://learn.microsoft.com/en-us/azure/vpn-gateway/vpn-gateway-vpn-faq) gives TCP 443 for SSTP/OpenVPN and UDP 500/4500 plus ESP for IKEv2/IPsec tunnels.

The [connection REST GET schema](https://learn.microsoft.com/en-us/rest/api/network-gateway/virtual-network-gateway-connections/get?view=rest-network-gateway-2025-05-01) supplies gateway references, connection type and status, and a local network gateway peer reference. The collector lists connections once per resource group through the existing bounded scheduler and retains only those references and state fields; it omits the shared key and tunnel secrets. The gateway collector already lists gateway resources by resource group. The selection plan now includes public IPs and the cached connection inventory for each selected gateway.

The native detector reports a configured public tunnel listener on a resolved global public IP and records a connected local gateway or foreign-subscription peer. It keeps unresolved addresses, tunnel protocols, connection lists, and incomplete ownership as `UNKNOWN` evidence. A gateway LIST response can omit optional/default properties, so absence of P2S configuration or connections is not used as proof of a closed listener. RADIUS secrets are removed by the collector metadata projection.
