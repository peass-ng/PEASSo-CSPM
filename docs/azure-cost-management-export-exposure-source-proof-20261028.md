# Cost Management export exposure source proof

- The [Exports List API](https://learn.microsoft.com/en-us/rest/api/cost-management/exports/list?view=rest-cost-management-2025-03-01) reads configured exports at subscription, resource-group, management-group and billing scopes. `properties.deliveryInfo.destination.resourceId` names the storage account that receives the data. `azure_cost_exports_native.collect` lists each selected subscription, observed resource group and observed management group once through the existing per-scan request cache, validates export identity, and retains destination identity and schedule metadata only.
- The same API's `ExportDeliveryDestination` definition permits a partner to use `storageAccount` plus `sasToken` instead of an ARM resource ID, including a storage account in any tenant. The API always obfuscates the returned SAS token and does not return an owner tenant/subscription for that destination. The collector drops `sasToken` entirely. A read-only API scan cannot decide whether this SAS-form destination belongs to a third party, or enumerate recipients holding storage SAS grants.
- `peaso.analysis.internet_exposure._azure_cost_export` flags a configured export from a subscription/resource group to a different subscription, and a management-group export to a subscription with a known different tenant. Same-subscription destinations are blocked for this export route; SAS-form and unresolved ownership remain UNKNOWN. Existing Storage analysis independently assesses the receiving account when it is in selected inventory.
- Billing-account and other billing hierarchy scopes are outside the selected subscription/management-group scan inventory. Their exports require independently authorized billing-scope discovery; the current collector makes no absence claim for them.
