# Azure App Configuration perimeter exposure source proof

Microsoft's [App Configuration network security guide](https://learn.microsoft.com/en-us/azure/azure-app-configuration/concept-network-security) states that an enforced network security perimeter association governs inbound public access and overrides the store's `publicNetworkAccess` value. The [transition behavior table](https://learn.microsoft.com/en-us/azure/private-link/network-security-perimeter-transition) shows that Learning/Transition mode also permits traffic through either perimeter rules or the store's public access rules. `SecuredByPerimeter` with no association blocks public inbound traffic.

The [per-store NSP configuration LIST API](https://learn.microsoft.com/en-us/rest/api/appconfiguration/network-security-perimeter-configurations/list-by-configuration-store?view=rest-appconfiguration-2025-08-01-preview) returns association mode, perimeter ID, inbound profile rules, and provisioning issues. Its inbound rules may allow public IP prefixes, Azure subscriptions, or another perimeter. The [perimeter association LIST API](https://learn.microsoft.com/en-us/rest/api/network-security-perimeter/network-security-perimeter-associations/list?view=rest-network-security-perimeter-2025-05-01) supplies the protected resource IDs of members of the same perimeter. [Microsoft's NSP diagnostic log definitions](https://learn.microsoft.com/en-us/azure/private-link/network-security-perimeter-diagnostic-logs) confirm intra-perimeter inbound access is allowed.

The collector reads each selected store's full management GET once, its NSP configuration once, then each referenced perimeter's associations once through the scan request cache. It retains only IDs, modes, settled state, and inbound rule source metadata. The detector reports public prefixes and foreign subscription rules, including a foreign resource associated with the same perimeter. It returns `UNKNOWN` for incomplete or unsettled association/profile/membership data. Client authentication still applies to allowed network paths.

The [configuration store GET schema](https://learn.microsoft.com/en-us/rest/api/appconfiguration/configuration-stores/get?view=rest-appconfiguration-2024-06-01) includes private endpoint connection IDs and approval state. The collector projects those references without free-form descriptions; a separate native assessment reports approved, provisioned connections from another subscription. `Automatic` public access uses the collected connection state: no connection leaves public access open, an approved connection closes it, and unsettled state is unresolved.

The [App Configuration Event Grid source guide](https://learn.microsoft.com/en-us/azure/event-grid/event-schema-app-configuration) documents key-value and snapshot change events. The [Event Subscriptions list-by-resource API](https://learn.microsoft.com/en-us/rest/api/eventgrid/controlplane/event-subscriptions/list-by-resource?view=rest-eventgrid-controlplane-2025-02-15) exposes destinations, expiration, and dead-letter resources. The collector reads subscriptions per store through the scan cache, keeps webhook hostnames without paths, query strings, or delivery attributes, and follows referenced same-subscription Monitor action groups once. The [Action Groups GET API](https://learn.microsoft.com/en-us/rest/api/monitor/action-groups/get?view=rest-monitor-2021-09-01) supplies receiver categories, enabled state, and destination references. The projection discards email addresses, phone numbers, webhook callback paths, and query strings. Native assessment reports external webhooks, notification channels, foreign-subscription resource destinations and dead letters; absent or malformed destination facts remain `UNKNOWN`.

The [App Configuration access-key LIST API](https://learn.microsoft.com/en-us/rest/api/appconfiguration/configuration-stores/list-keys?view=rest-appconfiguration-2024-06-01) returns bearer key values and connection strings, but no recipient or usage ownership. Its presence cannot establish whether a key was copied outside the tenant. The collector therefore does not request or retain keys; cross-tenant distribution of previously copied keys is an API visibility limit. The store's public and private ingress configuration is assessed above.
