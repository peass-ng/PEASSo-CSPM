# PostgreSQL Flexible Server exposure source proof

The existing read-only server LIST is upgraded to `2025-08-01`, whose [resource schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.dbforpostgresql/change-log/flexibleservers) includes the elastic `cluster` property. The collector already reads paged server configurations and firewall rules. It now retains only the `pgbouncer.enabled` value from the configurations LIST. [Microsoft's PgBouncer guide](https://learn.microsoft.com/en-us/azure/postgresql/connectivity/concepts-pgbouncer) identifies 6432 as its listener and 8432 for elastic cluster workers; the detector includes them only when PgBouncer is explicitly enabled, and the worker port only for a reported positive cluster size.

The [server LIST schema](https://learn.microsoft.com/en-us/rest/api/postgresql/servers/list?view=rest-postgresql-2024-08-01) includes private endpoint connections. When present, the collector validates and projects them from that response. Otherwise it uses the read-only paged [private endpoint connection LIST](https://learn.microsoft.com/en-us/rest/api/postgresql/private-endpoint-connections-part-1/list-by-server?view=rest-postgresql-2024-08-01). Denied or malformed inventory remains unknown. The [PostgreSQL networking guide](https://learn.microsoft.com/en-us/azure/postgresql/flexible-server/how-to-networking-servers-deployed-public-access-disable-public-access) says private endpoints remain a path when public access is disabled. An approved, provisioned connection owned by another subscription is reported as a third-party route, subject to database authentication.
