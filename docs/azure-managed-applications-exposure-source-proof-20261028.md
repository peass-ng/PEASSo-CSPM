# Azure Managed Applications publisher access source proof

- [Applications List By Subscription](https://learn.microsoft.com/en-us/rest/api/managedapplications/applications/list-by-subscription?view=rest-managedapplications-2019-07-01) documents the read-only `GET /subscriptions/{subscriptionId}/providers/Microsoft.Solutions/applications?api-version=2019-07-01`, `nextLink`, and the application fields `publisherTenantId`, `managementMode`, `authorizations`, `jitAccessPolicy`, and `provisioningState`. It also documents `parameters` and `outputs`, which the collector drops before snapshot storage.
- [Application Authorization](https://learn.microsoft.com/en-us/rest/api/managedapplications/applications/list-by-subscription?view=rest-managedapplications-2019-07-01#applicationauthorization) says the provider principal and role grant management permissions on the managed application's container resource group. The role determines the actual operations.
- [Managed Applications overview](https://learn.microsoft.com/en-us/azure/azure-resource-manager/managed-applications/overview) explains publisher-managed customer resources and customer-controlled just-in-time access.
- [JIT Requests List By Resource Group](https://learn.microsoft.com/en-us/rest/api/managedapplications/jit-requests-2/list-by-resource-group?view=rest-managedapplications-2019-07-01) is a separate read API for activation state. This change does not infer activation from the application object; JIT-enabled instances produce `UNKNOWN`.

`peaso/collectors/azure.py` uses the per-scan cached ARM reader and subscription LIST to collect application identities, validates the resource type and selected scope, and projects only management and authorization metadata. `peaso/analysis/internet_exposure.py` compares the publisher tenant with the verified subscription tenant. A succeeded foreign publisher-managed application with nonempty principal grants and explicitly disabled JIT is `FAIL`; customer-managed, same-tenant, and empty-grant applications are `PASS`; incomplete state or JIT activation is `UNKNOWN`.

Focused verification: `tests/test_peaso_azure_managed_application_exposure.py` checks the native call set, secret exclusion, foreign grant, customer-managed and JIT outcomes. No Azure write operation is used.
