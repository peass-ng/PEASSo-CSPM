# Managed Application publisher exposure source proof

- The [Applications List By Subscription API](https://learn.microsoft.com/en-us/rest/api/managedapplications/applications/list-by-subscription?view=rest-managedapplications-2019-07-01) returns `publisherTenantId`, `managementMode`, `managedResourceGroupId`, package `authorizations` (provider principal and role), JIT policy, and provisioning state. It also returns arbitrary parameters and outputs, which the collector discards before snapshot creation.
- Microsoft's [Managed Applications overview](https://learn.microsoft.com/en-us/azure/azure-resource-manager/managed-applications/overview) says publisher-managed applications grant the publisher access to the managed resource group in the customer tenant; unmanaged/customer-managed modes remove that publisher access. The [JIT documentation](https://learn.microsoft.com/en-us/azure/azure-resource-manager/managed-applications/request-just-in-time-access) says a JIT-enabled publisher retains read-only access and can request elevated access for a period.
- The [JIT requests LIST API](https://learn.microsoft.com/en-us/rest/api/managedapplications/jit-requests-2/list-by-resource-group?view=rest-managedapplications-2019-07-01) returns request state, parent application ID, publisher tenant, and schedule. The collector reads it once per resource group containing JIT-enabled applications and retains only these fields.
- `peaso.analysis.internet_exposure._azure_managed_application` reports a configured, provisioned managed application with a verified foreign publisher tenant as FAIL for publisher read access. Approved JIT requests are recorded as conditional elevation evidence; their effective time and role activation are not asserted from the request status alone. The child resources' own network and data exposure remain assessed under their resource types.
