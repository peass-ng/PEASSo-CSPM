## Bigtable direct-reader subcase added in v2

`analysis.gcp_bigtable_external_reader` reads the already cached `bigtable_table.iamPolicy`. An unconditional direct `roles/bigtable.reader` binding to a `serviceAccount:` identity whose email names a different GCP project is an observed cross-project table-read permission declaration. A conditional binding is UNKNOWN. Same-project service accounts, other roles, unavailable IAM and identities whose project cannot be parsed do not produce this finding. The role includes `bigtable.tables.readRows` ([Bigtable IAM roles](https://docs.cloud.google.com/bigtable/docs/access-control)); the table policy is read through the [Bigtable table IAM API](https://docs.cloud.google.com/bigtable/docs/reference/admin/rest/v2/projects.instances.tables/getIamPolicy). Bigtable does not support grants to `allUsers` or `allAuthenticatedUsers`, so this subcase does not claim anonymous access. It does not establish project ownership, IAM deny outcomes, table contents, or successful reads. Instance, project, view and inherited grants, custom roles, and other sharing paths remain open.

## Composer Airflow web-server subcase added in v3

`composer_environment` uses the already collected `config.airflowUri`, `state`, and `config.webServerNetworkAccessControl.allowedIpRanges`. A RUNNING environment with an observed HTTPS URI and no access-control object has a declared HTTPS network path from the internet; an explicit empty list or exclusively private CIDRs blocks direct internet sources. A public CIDR admits its source subset. Missing URI/state or malformed controls stay UNKNOWN. The finding records IAM authentication as a separate required layer and does not claim a user is authorized, a response was observed, or that other Composer interfaces are covered. A Private IP environment flag alone does not override the web-server allowlist. [Environment API fields](https://docs.cloud.google.com/composer/docs/reference/rest/v1/projects.locations.environments); [allow-all, allow-IP and deny-all semantics and IAM](https://docs.cloud.google.com/composer/docs/composer-1/create-environments).

## Cloud Scheduler OIDC target subcase added in v5

`analysis.gcp_scheduler_oidc_target` evaluates an ENABLED cached `scheduler_job.httpTarget` with an HTTP(S) URI and `oidcToken.serviceAccountEmail`. It reports the configured token-bearing outbound call and stores only the URI origin, never path/query, audience or body. Paused jobs, missing token configuration, malformed URLs and private IP targets do not produce this finding. Cloud Scheduler documents that HTTP targets are publicly accessible and that an OIDC token is attached when configured ([HTTP target jobs](https://docs.cloud.google.com/scheduler/docs/creating); [Job API](https://docs.cloud.google.com/scheduler/docs/reference/rest/v1/projects.locations.jobs)). The finding does not establish target ownership, a generated token value, job execution, successful delivery or token use. This reveals a distinct outbound integration vector, so the vector ledger grows from 11 to 12 PARTIAL rows while its subcase is implemented.

## Hierarchical firewall first-rule generalization added in v7

The cached per-interface effective response now sorts active ingress rules within the first `HIERARCHY` policy by priority. An explicit egress rule or disabled rule does not precede ingress evaluation. The first active ingress rule may have any unique valid priority; if it is a terminal allow/deny for all protocols, ports and public source families with no other match selectors, its decision is used. A narrower first rule, duplicate priority, malformed state or other attached policy remains UNKNOWN. This follows [Google's ordered policy evaluation](https://docs.cloud.google.com/firewall/docs/firewall-policies-rule-eval-order) and [getEffectiveFirewalls response](https://docs.cloud.google.com/compute/docs/reference/rest/v1/instances/getEffectiveFirewalls). GCP-E01 remains PARTIAL; vector and product counts do not change.

This version also corrects FAIL/UNKNOWN `observed` text for the Bigtable, Source Repository, Scheduler, Artifact Registry, Composer and terminal-firewall subcases. Each has four resource-first sentence lines with the recorded setting, possible impact and unresolved facts. No finding text states that a scan, check or test proved an effective request.
