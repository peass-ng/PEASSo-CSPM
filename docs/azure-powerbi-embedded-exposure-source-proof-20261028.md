# Power BI Embedded exposure source proof

- The [Power BI Embedded ARM API](https://learn.microsoft.com/en-us/rest/api/power-bi-embedded/) manages dedicated capacities. Its [capacity LIST](https://learn.microsoft.com/en-us/rest/api/power-bi-embedded/capacities/list?view=rest-power-bi-embedded-2021-01-01) includes `properties.administration.members`, so the Azure collector now projects that list and discards unrelated capacity configuration. The native detector flags administrator emails outside a complete set of the tenant's verified domains; same-domain identity ownership remains UNKNOWN.
- Workspace and report sharing live in the [Power BI REST API](https://learn.microsoft.com/en-us/rest/api/power-bi/), separately from the Azure Resource Manager capacity API. [Get Group Users](https://learn.microsoft.com/en-us/rest/api/power-bi/groups/get-group-users) returns workspace users only with Power BI scopes; [Get Report Users as Admin](https://learn.microsoft.com/en-us/rest/api/power-bi/admin/reports-get-report-users-as-admin) requires Fabric administrator or service-principal authorization. Those rights are not supplied by the `azure-mgmt-powerbidedicated` or `azure-mgmt-powerbiembedded` ARM clients.
- For app-owns-data embedding, Microsoft says [the application authenticates its customers](https://learn.microsoft.com/en-us/power-bi/guidance/develop-scalable-multitenancy-apps-with-powerbi-embedding). The [Embed Token API](https://learn.microsoft.com/en-us/rest/api/power-bi/embed-token) generates tokens but provides no operation to enumerate a customer's application users or all issued tokens. The effective third-party viewing audience therefore cannot be recovered from a read-only Azure/Power BI management scan, even if workspace permissions are separately collected.
