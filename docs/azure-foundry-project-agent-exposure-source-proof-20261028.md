# Microsoft Foundry project and agent exposure source proof

The [Foundry architecture](https://learn.microsoft.com/en-us/azure/foundry/concepts/architecture) identifies `Microsoft.CognitiveServices/accounts` as the top-level Foundry resource and `Microsoft.CognitiveServices/accounts/projects` as its project subresource. The [ARM project LIST](https://learn.microsoft.com/en-us/rest/api/microsoftfoundry/accountmanagement/projects/list?view=rest-microsoftfoundry-accountmanagement-2025-06-01) is read-only, paged, and returns project identity, provisioning state and endpoints. The existing account LIST supplies public network access, network ACL and private endpoint connection metadata. [Foundry network guidance](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/virtual-networks) says the account network rule applies to all projects and protocols.

The new child collector reads projects only for selected `AIServices` accounts. It retains names, IDs, readiness and HTTPS endpoint hosts; URL paths, query strings, tags, arbitrary fields and credentials are discarded. Analysis joins each project to its exact parent account and reports authenticated TCP/443 exposure when parent public access and firewall permit a public source. It also detects approved private endpoints in a different subscription, including when public access is disabled. Missing states, ACLs, endpoints or private-link evidence remain UNKNOWN.

The [Foundry Agents REST API](https://learn.microsoft.com/en-us/rest/api/microsoft-foundry/aiproject) documents a project-scoped list and GET using the Foundry `https://{account-name}.services.ai.azure.com/api/projects/{project-name}` endpoint. The collector follows the list cursor, then reads each agent's full endpoint configuration once through the per-scan cache. It persists only serving status, protocol names, public Microsoft 365 Activity setting, and authorization scheme types and selected allow lists. [Endpoint authorization guidance](https://learn.microsoft.com/en-us/azure/foundry/agents/concepts/agent-endpoint-authorization) distinguishes Azure RBAC, AgentBlueprint and Bot Service schemes. [Publishing guidance](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/publish-copilot-virtual-network?view=foundry) confirms `enable_m365_public_endpoint=true` opens a source-IP-filtered public Activity route even with project public network access disabled. Native analysis flags that route, preserves the channel authentication type, and leaves scheme consent/audience questions unresolved.

The same [Foundry REST reference](https://learn.microsoft.com/en-us/rest/api/microsoft-foundry/aiproject) defines a read-only, paged connection LIST that does not populate credentials. Its separate credential-populating operation is a POST and is never used. The collector projects the connection type, credential type and HTTPS destination host or ARM target ID; it drops URL paths, query strings, credential values and arbitrary metadata. Native analysis records the configured destination as conditional because LIST cannot prove an agent actually used the connection or sent data to it.

Complete third-party access to a Foundry account remains undecidable from read-only management configuration: account keys can be copied, and a later scan cannot enumerate the holders or downstream uses of copied keys. Microsoft's [keyless authentication guidance](https://learn.microsoft.com/en-us/azure/developer/ai/keyless-connections) confirms anyone with a valid service key can authenticate. Connected Storage, Search and Key Vault resources have independent governance boundaries and are assessed on their own resource rows.
