# Purview account endpoint and private-share source proof

The [Purview Accounts LIST API](https://learn.microsoft.com/en-us/rest/api/purview/accounts/list-by-subscription?view=rest-purview-2021-12-01) returns account provisioning state, `publicNetworkAccess`, catalog/scan/guardian endpoint URLs, managed-resource public access, and private endpoint connections. The existing collector reads this subscription LIST. A new projection keeps only validated HTTPS hostnames and safe access, managed-resource and private-link metadata; it drops URL paths, query strings, AWS connector external IDs, and all unrelated account fields.

Native analysis detects authenticated public HTTPS account endpoints for a succeeded account with enabled public access and approved private endpoint connections from other subscriptions even when public access is disabled. It leaves managed Storage/Event Hub reachability unresolved for service-specific review. [Purview access guidance](https://learn.microsoft.com/en-us/purview/data-gov-classic-permissions) says Data Map roles are assigned on collections in the governance portal, independently of the ARM account. The `azure-mgmt-purview` account API does not return those effective collection role grants, so complete third-party catalog access cannot be decided from that management API alone. The wider Microsoft Purview product review remains open for data-plane permissions and sharing.
