# Azure Attestation provider exposure source proof

- [Azure Attestation provider schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.attestation/2021-06-01/attestationproviders) defines `publicNetworkAccess` as Enabled or Disabled and `tpmAttestationAuthentication`. The [SDK status model](https://learn.microsoft.com/en-us/python/api/azure-mgmt-attestation/azure.mgmt.attestation.models.statusresult?view=azure-python) also returns `attestUri`, `status`, and `trustModel` from provider read operations. The [Azure CLI list command](https://learn.microsoft.com/en-us/cli/azure/attestation?view=azure-cli-latest#az-attestation-list) invokes the subscription provider LIST. The collector reads it once per selected subscription and projects only these fields; it discards policy signing certificates and all URI path/query text.
- [Azure Attestation network guidance](https://learn.microsoft.com/en-us/azure/attestation/secure-attestation) says `publicNetworkAccess: Disabled` stops public data-plane traffic. Native analysis reports a Ready provider with Enabled public access and a valid HTTPS attestation host as FAIL on TCP 443, Disabled as PASS for the public path, and missing/ambiguous state as UNKNOWN.
- [Azure Attestation trust models](https://learn.microsoft.com/en-us/azure/attestation/basic-concepts) explain that the Isolated model authorizes policy changes through possession of a private signing key whose public certificate is trusted by the provider. The ARM API lists trusted public certificates, not who possesses corresponding private keys. A read-only scan therefore cannot enumerate every third party able to change isolated-model policy. This is a specific API limit on complete third-party exposure assessment, independent of the public-network verdict.
