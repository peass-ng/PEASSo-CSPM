# Microsoft Defender for Cloud notification/export source proof

- [Security Contacts List](https://learn.microsoft.com/en-us/rest/api/defenderforcloud/security-contacts/list?view=rest-defenderforcloud-2023-12-01-preview) is already collected. Its response includes `isEnabled`, semicolon-separated `emails`, notification sources, and role-based notification settings. The native detector reports enabled alert delivery to an email outside verified Entra domains, while incomplete domain/source evidence and role-only delivery remain UNKNOWN. The official LIST example uses singular `Microsoft.Security/securityContact` for a resource returned by the plural collection path; both type spellings are accepted.
- [Automations List](https://learn.microsoft.com/en-us/rest/api/defenderforcloud/automations/list?view=rest-defenderforcloud-2023-12-01-preview) is a read-only, paged subscription GET. Its actions identify Event Hub, Logic App, or Log Analytics Workspace targets and sources identify event types. The collector retains only action type, target ARM resource ID, source type, and enabled state; it drops rules, descriptions, connection strings, and trigger URIs. The detector reports enabled security-event routes to another subscription.
- The [automation action schema](https://learn.microsoft.com/en-us/rest/api/defenderforcloud/automations/create-or-update?view=rest-defenderforcloud-2023-12-01-preview) states that Event Hub `connectionString` and Logic App trigger `uri` are omitted from read responses. The API returns target resource IDs but cannot enumerate holders of issued Event Hub SAS credentials or downstream Logic App recipients. The read-only ARM state therefore cannot establish every third party that may consume an export, even when the configured destination remains in the source subscription.
