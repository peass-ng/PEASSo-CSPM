# Azure flexible federation source proof (2026-10-28)

[Microsoft Graph beta federated identity credentials](https://learn.microsoft.com/en-us/graph/api/resources/federatedidentitycredential?view=graph-rest-beta) expose `claimsMatchingExpression`, which is absent from the v1.0 credential representation. The existing per-application read now uses one beta LIST with an exact `$select` for `id`, `name`, `issuer`, `subject`, `audiences`, and `claimsMatchingExpression`. Projection retains only the expression language version and bounded value; descriptions and other response fields are dropped. A denied or malformed read preserves incomplete coverage. The [managed-identity ARM schema](https://learn.microsoft.com/en-us/azure/templates/microsoft.managedidentity/userassignedidentities/federatedidentitycredentials) exposes the same expression in the `2025-05-31-preview` child LIST, replacing the older child version without an extra call.

The read-only Graph batch allowlist now admits only that exact beta app-credential URL and the already reviewed beta group-members URL. The existing first-page batching and direct fallback preserve per-scan read caching and the denied/partial status boundary.

[Microsoft's flexible credential guide](https://learn.microsoft.com/en-us/entra/workload-id/workload-identities-flexible-federated-identity-credentials) defines `claims['...'] eq|matches '...'` conjunctions. GitHub requires `sub` plus immutable `repository_id` or `repository_owner_id`, and GitLab mutable subjects require `project_id`; the analyzer reports these recognized selectors as MANUAL because issuer ownership is not verified. A Terraform Cloud `sub` wildcard broad enough to admit arbitrary workloads is FAIL. Unsupported versions, operators, shapes, and missing immutable selectors stay UNKNOWN; expression text is never inferred from an exact `subject`.
