# Azure Monitor receiver and diagnostic export source proof

The [action-group LIST API](https://learn.microsoft.com/en-us/rest/api/monitor/action-groups/list-by-subscription-id?view=rest-monitor-2021-09-01) returns enabled state and receiver lists, including webhook `serviceUri`, Logic App callback URLs, Function trigger URLs, email addresses and Event Hub tenant/subscription IDs. URLs can contain secret path or query material. The collector already reads action groups once per subscription; its projection now retains only URL hostnames, email domains and validated Event Hub tenant/subscription IDs. The prior compliance representation remains marked incomplete, while a separate exposure projection records receiver metadata without secrets.

The [diagnostic-setting LIST API](https://learn.microsoft.com/en-us/rest/api/monitor/diagnostic-settings/list?view=rest-monitor-2021-05-01-preview) exposes enabled log/metric categories and destination ARM IDs for Event Hub, Storage, Log Analytics and Marketplace partners. The [subscription variant](https://learn.microsoft.com/en-us/rest/api/monitor/subscription-diagnostic-settings/list?view=rest-monitor-2021-05-01-preview) has the same destination fields. [Legacy log profiles](https://learn.microsoft.com/en-us/rest/api/monitor/log-profiles/list?view=rest-monitor-2016-03-01) return Storage and Service Bus rule destinations. Existing cached reads supply these facts; no new API calls are needed.

Native exposure assessment detects enabled action-group delivery to a declared foreign Event Hub tenant or subscription and enabled diagnostic/log-profile delivery to another subscription or a Marketplace partner. Disabled groups and wholly disabled categories block delivery. Webhook hostnames and mailbox domains are retained as candidates only: the management API cannot establish their operator or enumerate downstream recipients after a Logic App, Function, webhook or destination workspace forwards an alert. Thus full third-party receipt remains impossible to decide from Monitor read APIs.
