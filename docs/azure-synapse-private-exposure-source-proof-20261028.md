# Azure Synapse private exposure source proof

The read-only [workspace private endpoint connection LIST](https://learn.microsoft.com/en-us/rest/api/synapse/resourcemanager/private-endpoint-connections/list?view=rest-synapse-resourcemanager-2021-06-01) returns the endpoint ARM ID, approval status, and provisioning state. The collector makes one cached, paginated child LIST per workspace and validates child identities. `internet_exposure._azure_synapse_workspace` detects approved, provisioned endpoints in another subscription even if public network access is disabled. Missing or inconsistent inventory stays UNKNOWN.

The [Synapse access-control overview](https://learn.microsoft.com/en-us/azure/synapse-analytics/security/synapse-workspace-access-control-overview) separates Azure resource roles, Synapse roles, and SQL data-plane permissions. SQL pool access can be granted with scripts inside the pool, and [database principals and grants](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-database-principals-transact-sql?view=sql-server-ver15) require SQL queries. The `azure-mgmt-synapse` ARM API cannot enumerate those effective data-plane grants, so an ARM-only scan cannot prove complete third-party SQL access.
