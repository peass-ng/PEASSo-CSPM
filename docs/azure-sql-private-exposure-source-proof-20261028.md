# Azure SQL logical server private exposure source proof

The read-only [private endpoint connection LIST](https://learn.microsoft.com/en-us/rest/api/sql/private-endpoint-connections/list-by-server?view=rest-sql-2023-08-01) returns an endpoint ARM ID, approval status, and provisioning state for each logical server connection. The collector uses one cached, paginated child LIST per server and validates the child identity. `internet_exposure._azure_sql` reports approved, ready foreign-subscription private endpoints even when `publicNetworkAccess` is disabled. Incomplete lists stay UNKNOWN.

The [Azure SQL firewall documentation](https://learn.microsoft.com/en-us/azure/azure-sql/database/firewall-configure?view=azuresql) states that database-level firewall rules are created and managed only with Transact-SQL. The [catalog view](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-database-firewall-rules-azure-sql-database?view=azuresqldb-current) must be queried within each database by a principal able to connect. The Azure management API and `azure-mgmt-sql` cannot enumerate those database-level rules or database-contained user grants; a management-plane-only scan cannot prove comprehensive SQL access exposure.
