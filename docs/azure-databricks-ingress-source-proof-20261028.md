# Azure Databricks context-based ingress read

An owner-approved Databricks account ID and an explicitly supplied account OAuth token already authorize the native Account/ARM workspace join. This change reads the [workspace network option](https://docs.databricks.com/api/networking/v1/workspace-network-option) for each joined workspace ID, then the exact [account network policy](https://docs.databricks.com/api/networking/v1/account-network-policy) named by that binding. The transport permits only those two account GET paths, disables proxies and redirects, bounds response bytes, and rejects duplicate JSON keys. It retains the enforced public ingress mode, allow/deny rule counts, normalized source ranges and broad identity classes for workspace-UI and workspace-API rules, and only a bounded `sql` or all-API scope marker; rule labels, selected identity IDs, other scope names, and the dry-run policy are not copied into the snapshot. The collector validates the same projected policy shape after the transport read so live and injected transports follow one join boundary.

The analyzer treats `RESTRICTED_ACCESS` with an explicitly empty allow-rule array as a block of direct public workspace ingress. `FULL_ACCESS` resolves that policy layer; the workspace IP access list layer must still allow the path before the listener is classified reachable. For a nonempty restricted policy, a workspace-UI user or recognized workspace-API user/service-principal allow rule can prove a public path only when a concrete global IPv4 address survives the workspace IP lists and every deny that applies to that destination and identity class. An omitted authentication selector covers both classes; `ALL_USERS` and `ALL_SERVICE_PRINCIPALS` cover their respective classes. UI-only denies do not cancel API witnesses, and API-only denies do not cancel UI witnesses. The source witness checks every interval separated by the recorded allow/BLOCK/context CIDR endpoints and Python's IPv4 special-use boundaries. An API allow rule is recognized for all APIs or the documented `sql` scope with READ or ALL qualifier; unsupported scopes, selected identities, unmatched deny shapes, and cases without a concrete surviving source remain `UNKNOWN`. Missing owner approval, denied account reads, incomplete ARM/account joins, and malformed policy data remain unknown. [Databricks ingress guidance](https://learn.microsoft.com/en-us/azure/databricks/security/network/front-end/context-based-ingress) documents workspace UI and API destinations, broad identity classes, deny-before-allow, default deny in restricted mode, and joint enforcement with workspace IP lists.
