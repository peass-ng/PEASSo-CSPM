# Azure Databricks context-based ingress read

An owner-approved Databricks account ID and an explicitly supplied account OAuth token already authorize the native Account/ARM workspace join. This change reads the [workspace network option](https://docs.databricks.com/api/networking/v1/workspace-network-option) for each joined workspace ID, then the exact [account network policy](https://docs.databricks.com/api/networking/v1/account-network-policy) named by that binding. The transport permits only those two account GET paths, disables proxies and redirects, bounds response bytes, and rejects duplicate JSON keys. It retains only the enforced public ingress mode and allow/deny rule counts; rule labels, identities, and the dry-run policy are not copied into the snapshot.

The analyzer treats `RESTRICTED_ACCESS` with an explicitly empty allow-rule array as a block of direct public workspace ingress. `FULL_ACCESS` resolves that policy layer; the workspace IP access list layer must still allow the path before the listener is classified reachable. Nonempty allow-rule arrays remain `UNKNOWN` until the identity, network source, and destination predicates are evaluated. Missing owner approval, denied account reads, incomplete ARM/account joins, and malformed policy data remain unknown. [Databricks ingress guidance](https://learn.microsoft.com/en-us/azure/databricks/security/network/front-end/context-based-ingress) documents default deny in restricted mode and the joint enforcement with workspace IP lists.
